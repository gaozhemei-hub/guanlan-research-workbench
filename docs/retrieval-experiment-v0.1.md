# 本地检索基线实验 v0.1

日期：2026-10-25。此实验为 RAG 接入前的离线检索底座，不是产品已支持 RAG 问答的声明。

## 已实现

`server/retrieval.py` 使用 SQLite 保存派生索引，按非空文本行建立段落块，保留来源、版本、原文字符位置与内容哈希。词法基线使用中文双字片段、英文词与 BM25 排序；没有 embedding、重排模型或生成模型，也没有新增第三方依赖。

同版本相同内容重复导入得到相同结果；同版本改内容会拒绝。新版本在事务中替换旧版本；构建或写入失败会保留原索引并标为 stale。删除或版本变化后，旧块不能通过当前引用校验。工作区参与索引键和检索过滤。stale 内容可以带状态被检索，但不能通过引用有效性检查。

索引仅用于独立实验，没有 HTTP 接口，也不会自动读取浏览器记录。当前不提供历史版本查询、用户身份鉴权、答案缓存、自动重建或完整浏览器同步。工作区隔离测试不能替代未来接口的授权校验。

## 样本与方法

公开样本见 `examples/retrieval-benchmark.json`：8 个单段来源、12 个问题及预期来源标签，全部为 AI 编写的原创教学内容。标签不是独立人工评审；没有使用私人纪要、实习资料或真实模型输出。

问题划分为开发组 5 题和比较组 7 题；本轮未根据结果调整分词、参数或标签。比较组已经运行，不能再称为未见过的盲测集；后续调参应使用开发组，并在最终验收前新增独立材料与问题。样本 SHA256：`6a2ce9d5f2ff6785b6e05557ef450e7bebbfe9746c5577472dad09b65bbdc734`。

运行 `.venv/bin/python scripts/evaluate-retrieval.py`，结果保存到忽略目录 `data/retrieval-baseline/`。索引在内存中创建并关闭。每次报告记录样本哈希、方法、逐题来源排序、耗时和引用检查结果。

## 首次结果

| 指标 | 开发组 | 比较组 |
| --- | --- | --- |
| 有答案问题数 | 4 | 5 |
| 前三条平均来源召回率 | 1.00 | 1.00 |
| 前三条首个相关结果倒数排名均值 | 1.00 | 0.90 |
| 无答案问题数 | 1 | 2 |
| 无答案但返回候选片段 | 0 | 2 |

召回率按每题命中的预期来源占比计算后取均值；不是回答正确率。8 段材料中取前 3 段的任务较简单，结果不能外推到大量真实材料。引用检查仅检测返回文本是否存在于当前索引，不评判事实真假、论证支持或投资价值。

“黄金明天的精确价格是多少”等题没有答案，却仍返回词汇相关候选。这说明后续生成层必须区分相关内容与充分证据；不能凭非空搜索结果生成确定结论。当前实验根本不生成答案。

## 下一步验收

1. 扩大原创语料，加入相似但条件相反、日期不同、多段长文和跨来源证据；独立留出最终验收题。
2. 在同一标签下比较向量、混合与重排方案，同时记录模型版本、token 限制、延迟和成本。未运行的方案不填指标。
3. 接入前验证浏览器显式同步、删除、旧索引提示与引用回跳。材料保留在用户控制之下。
4. 如引入生成，单独验证证据不足时的行为与答案支持程度；不以逐字引用通过替代支持性判断。
