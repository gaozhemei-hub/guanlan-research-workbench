# 迭代 001：先验证研究流程，再补齐正式 PRD

日期：2026-10-11

## 本轮决定

用户认可产品边界，但认为 PRD 仍需打磨。按用户决定，暂停重写 PRD，先做底座验证和简单可操作原型。PRD v0.1 保留为历史设计草稿，不视为本轮实现说明。

## 具体取舍

| 问题 | 本轮做法 | 原因与后续验证 |
|---|---|---|
| 没有明确标的能否开始？ | 默认从研究假设开始，允许候选对象为空 | 贴合发起者的真实输入；待用户试用确认空名单是否仍有用 |
| 三个 Tab 会不会只是重复总结？ | 框架放判断和条件；证据放验证任务；线索放影响路径和候选对象 | 先用原型观察分工是否清楚 |
| 新资料如何改变旧研究？ | 保存待审建议 → 对比 → 确认更新 → 留存旧版本 | 把产品差异落在可操作流程上 |
| 新建议与手动修改冲突怎么办？ | 检查 baseVersion；版本已变则阻止直接应用 | 避免旧建议覆盖用户的新判断 |
| 如何避免把确认当成正确？ | 状态使用“已确认，待验证” | 确认整理与投资结论成立是不同事件 |
| 是否先接真实模型？ | 此原型使用明确标注的教学示例，任意导入进入手动模式 | 模型与底座尚未配置完成，不把预置内容冒充 AI 实测 |
| 是否重做资料工具？ | 继续验证 Open Notebook 的来源/笔记/Transformation 接口 | 界面原型暂独立；不宣称已经基于其改造完成 |

## 已发现并修复

- 桌面截图发现问题列表的 HTML 容器未闭合，造成阶梯式挤压；已修复并重跑浏览器测试。
- 保存待审更新时保留原判断；确认前不变更研究版本。
- 支持/削弱/不足以判断的证据状态要求填写理由并关联有效段落。
- 导入正文按文本显示，HTML 标签不会执行。

## 自动检查

`tests/prototype-smoke.cjs` 在独立 Chrome 无头浏览器中执行；分别测试本地 HTTP 页面和打包后的 file:// HTML。通过：

1. 两种教学入口正常加载。
2. 原文段落高亮定位。
3. 待审建议不改变当前判断。
4. 用户确认后版本增加、旧判断留存。
5. 刷新后保存结果仍存在。
6. 旧建议与新版本冲突时不能直接应用。
7. 缺少理由和引用时不能标成支持证据。
8. 无公司候选时保留有效空状态。
9. 输入 HTML 字符串不会执行脚本。
10. JSON 导出被浏览器触发。
11. UTF-8 MD 文件导入并刷新保留。
12. 390 px 窄屏无整页横向溢出。
13. 上述流程没有浏览器 JavaScript 错误。

桌面、手机截图另保存于 `prototype/`。这不是完整 PRD 验收，也不是用户测试、投资正确率或 AI 评测结果。

## 下一轮需要验证

- 用户是否理解三个 Tab 的不同作用，以及愿不愿意用它完成自己的研究。
- 选定底座后，接通一条“原文 → 模型结构化草稿 → 片段引用核验 → 用户确认”链路。
- 对方法类、事件类、信息不足、矛盾材料分别评测，不以输出篇幅作为质量标准。
- 只有实测后，再改写正式 PRD 的流程、异常、指标与技术约束。

## 底座恢复验证补充

Open Notebook 的健康检查、资料导入读回、笔记编辑保存、模板保存、异步 worker 处理均完成实测，最终 7 项通过。冷启动曾出现 45 秒同步超时和 25 秒异步等待超时，已保留失败 JSON；缓存就绪后复测通过。生成模型、嵌入与完整界面集成仍未验证。详见底座验证记录。
