# 本地 AI 接口配置

本版接入 **Chat Completions 兼容 API**，只在服务端读取密钥；前端不保存密钥。真实服务商尚未指定，兼容性需要填写后测试。

1. 在项目根目录复制 `.env.example` 为 `.env`。
2. 在本机文件中填写服务商给出的地址、密钥、模型名。不要把密钥发进聊天或提交 GitHub。
3. 启动或重启 `prototype/启动原型.command`，进入「数据与设置」检查是否识别到配置。
4. 用一份不含私人资料的短教学材料点击「AI 辅助拆解」，核对引用和归类后确认归档。

```dotenv
LLM_BASE_URL=https://服务商提供的基础地址/v1
LLM_API_KEY=你的密钥
LLM_MODEL=服务商支持的模型名称
```

BASE_URL 必须 HTTPS，不带 `/chat/completions`；服务端会追加此路径。不允许用户名密码嵌在 URL 内，也不自动追随重定向发送密钥。环境变量优先于 `.env`。

调用使用 `messages`、`response_format: {type: "json_object"}`、`max_completion_tokens: 3500`。部分兼容服务商对参数或 JSON 模式支持不同；如果出现 HTTP 400，需要按该服务商文档调整适配器，不重复盲试或自动消耗额度。接口格式参考 [OpenAI 官方 Chat Completions 文档](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。本项目未默认指定模型。

## 发送范围

仅在主动点击分析按钮时，发送当前导入材料的全文（最多 20,000 字符）及研究节点说明。材料内容被作为数据，内部的指令不改变分析任务。没有自动批量上传、检索浏览器记录或发送其他材料。

AI 输出先经过：JSON 结构 → 节点枚举 → 段落范围 → 逐字引文匹配检查。任何一项失败，整批不写入研究。通过后仍是待审建议：原文有这句话，不代表观点为真，也不保证模型概括准确。

模型返回最多 5 条建议，用户可切换、修改、逐条归档。AI 分析不会自动生成仓位或买卖信号，也不直接覆盖框架与历史判断。

## 已验证与待验证

已验证：模拟成功响应、错误字段、不存在的节点、越界段落、伪造引文、缺少配置时不发网络请求。真正服务商调用尚未执行，模型效果、费用、时延与中文分类质量尚待测量。

配置显示「已配置」只说明字段完整，不代表服务商鉴权成功。不要将模拟响应测试写成真实模型验收。
